Mental model: why NumPy exists

A Python list is an array of pointers to full Python objects. Adding two lists of a million numbers means a million type checks, a million object lookups, and a million new objects. NumPy's ndarray is different:

  • One contiguous block of memory holding raw, fixed-size values (no per-element objects).
  • One dtype for the whole array (homogeneous), so the CPU can process it in tight compiled C loops, often with SIMD.
  • Metadata describes how to interpret the block: shape, dtype, strides.
  • Vectorization: you write a + b, NumPy loops in C. Python loops over arrays are almost always the wrong tool.
import numpy as np

lst = list(range(1_000_000))
arr = np.arange(1_000_000)

[x * 2 for x in lst]   # ~50-80 ms   (Python loop)
arr * 2                # ~1-2 ms     (C loop, no Python objects)

Everything in NumPy is built from three ideas: ndarray (the container), ufuncs / vectorization (the compute), and broadcasting (the rule that lets shapes differ).

Convention. import numpy as np always. This guide targets NumPy 2.x; version differences are flagged.

Axes. For shape (2, 3): axis 0 runs down the rows (length 2), axis 1 runs across the columns (length 3). For 3-D (depth, rows, cols), axis 0 is depth. A reduction with axis=k removes axis k from the shape.

Strides and order. Default is C order (row-major): the last index varies fastest in memory. Fortran order (order='F') is column-major. Transposing just swaps strides — no data moves — which is why a.T is O(1) and returns a view.

Rules worth memorising

  • Upcasting in mixed operations: int array + float gives float64; int8 array + int64 array gives int64.
  • Overflow wraps silently for arrays: np.array([127], dtype=np.int8) + 1 gives [-128].
  • Assigning floats into int arrays truncates: a[0] = 3.9 stores 3.
  • NaN needs a float dtype (int arrays cannot hold NaN).
  • a.dtype = ... reinterprets bytes (dangerous). Use astype.
  • NumPy 2 note: Python scalars are "weak" in promotion, so np.float32(3) + 3.0 stays float32. Out-of-range Python ints assigned into small dtypes raise OverflowError.

Broadcasting

Broadcasting lets NumPy operate on arrays of different shapes without copying data.

The rule (compare shapes from the LAST axis backwards): 1. If the arrays have different ndim, prepend 1s to the shorter shape. 2. Two dimensions are compatible if they are equal or one of them is 1. 3. The result dimension is the larger of the two; size-1 dims are stretched. 4. Otherwise: ValueError: operands could not be broadcast together.

A     (5, 3)          A     (4, 1)          A     (2, 3)
B        (3,)         B        (3,)         B        (2,)
--------------        --------------        --------------
=     (5, 3)          =     (4, 3)          X  3 vs 2 -> error

X = np.arange(12).reshape(4, 3)
X - X.mean(axis=0)               # centre each column: (4,3) - (3,)
X / X.sum(axis=1, keepdims=True) # row-normalise: (4,3) / (4,1)   <- keepdims avoids reshape
np.arange(3)[:, None] + np.arange(4)   # outer-sum grid (3, 4)

# Distance matrix without loops
P = np.random.rand(5, 2)
D = np.sqrt(((P[:, None, :] - P[None, :, :]) ** 2).sum(axis=-1))   # (5, 5)

Fix for "(2,3) + (2,)": turn the vector into a column: v[:, None] or v.reshape(-1, 1).

Copies, views, memory and performance
  • View: new array object, same buffer (a[:3], a.T, a.reshape when contiguous, a.view(), np.ravel).
  • Copy: fresh buffer (a.copy(), a.flatten(), np.sort(a), fancy/boolean indexing, astype).
  • a.base is None means the array owns its data; otherwise a.base is the parent.
  • np.shares_memory(a, b) answers definitively.

Performance checklist

  1. Replace Python loops with vectorised expressions, np.where, boolean masks, broadcasting.
  2. Avoid growing arrays in a loop (np.append): collect in a list, convert once, or preallocate with np.empty.
  3. Choose smaller dtypes when precision allows (float32, uint8) — halves memory and bandwidth.
  4. Prefer contiguous arrays; np.ascontiguousarray(x) when needed.
  5. np.vectorize is a convenience loop, not a speedup. For truly custom kernels use Numba or Cython.
  6. Use out= and in-place ops (a += 1) to avoid temporaries; np.einsum and @ for contractions.
  7. Use %timeit to measure; np.__config__.show() reveals the BLAS in use.
Top gotchas (memorise these)
  1. b = a is not a copy — use a.copy().
  2. Slices are views; fancy/boolean indexing copies.
  3. np.zeros(3, 3) is wrong — shape is one tuple: np.zeros((3, 3)).
  4. Use &, |, ~ with parentheses — not and, or, not.
  5. np.std default ddof=0; pandas default ddof=1.
  6. NaN != NaN and NaN propagates in NumPy reductions (np.mean); pandas skips it.
  7. np.array_equal / np.allclose for comparisons — not == with if.
  8. Integer overflow wraps silently in arrays (int8, uint8).
  9. np.round rounds half to even (2.5 → 2.0).
  10. a.sort() returns None; np.sort(a) returns a sorted copy.
  11. np.arange with float step is unreliable; use linspace.
  12. np.concatenate((a, b)) takes one sequence; np.stack adds an axis.
  13. a.T on a 1-D array does nothing — use a[:, None].
  14. np.random.randint(a, b) excludes b; Generator.integers too (unless endpoint=True).
  15. Ragged lists need dtype=object — and usually mean you want pandas or a different structure.

Mental model: Series, DataFrame, Index

pandas adds labels and tabular semantics on top of NumPy-style arrays.

  • Series = 1-D array of values + an Index (labels) + a name + a dtype.
  • DataFrame = 2-D table: an ordered dict of Series sharing one row Index, with a columns Index. Each column may have its own dtype.
  • Index = immutable, hashable labels (RangeIndex, Index, DatetimeIndex, MultiIndex, CategoricalIndex). Its job: lookup and automatic alignment.
import numpy as np
import pandas as pd

s  = pd.Series([10, 20, 30], index=["a", "b", "c"], name="score")
df = pd.DataFrame({"name": ["Ann", "Bob", "Cy"], "age": [28, 35, 41], "city": ["NY", "LA", "NY"]})

Three ideas power everything: vectorised ops on columns, alignment on labels, and split-apply-combine (groupby).

Versions. This guide covers pandas 2.x and 3.x. Big 3.0 changes: Copy-on-Write is always on (no more views/copies ambiguity, chained assignment never writes to the parent), text columns default to a dedicated str dtype (instead of object), and many long-deprecated features are gone. Version-specific notes are flagged as (2.x) / (3.0).

  1. loc slices include the end label; iloc slices exclude the end position.

NumPy case 2: k-nearest neighbours without loops

Problem. For each of 1,000 query points find its 3 nearest neighbours among 5,000 reference points in 2-D.

rng = np.random.default_rng(0)
ref = rng.random((5000, 2))
qry = rng.random((1000, 2))

# Pairwise squared distances via broadcasting: (1000,1,2) - (1,5000,2) -> (1000,5000,2)
d2 = ((qry[:, None, :] - ref[None, :, :]) ** 2).sum(axis=-1)      # (1000, 5000)

# Memory-friendlier identity: |a-b|^2 = |a|^2 + |b|^2 - 2 a.b
d2_fast = (qry**2).sum(1)[:, None] + (ref**2).sum(1)[None, :] - 2 * qry @ ref.T
print(np.allclose(d2, d2_fast))                                    # True

# k smallest per row: argpartition is O(n), then sort just those k
k = 3
idx = np.argpartition(d2, k, axis=1)[:, :k]                       # (1000, 3) unordered
order = np.take_along_axis(d2, idx, axis=1).argsort(axis=1)
nn = np.take_along_axis(idx, order, axis=1)                        # sorted neighbour indices

print(nn.shape, nn[0], np.sqrt(d2[0, nn[0]]).round(4))

What you learn: broadcasting with None/np.newaxis to build pairwise tables, the algebraic trick to avoid a 3-D temporary, argpartition for top-k, take_along_axis for row-wise gathering.

NumPy case 4: linear regression from scratch

Problem. Fit y = 3 + 2*x1 - 1.5*x2 + noise using linear algebra, then evaluate R².

rng = np.random.default_rng(42)
n = 500
X = rng.normal(size=(n, 2))
y = 3 + 2 * X[:, 0] - 1.5 * X[:, 1] + rng.normal(scale=0.5, size=n)

A = np.c_[np.ones(n), X]                     # design matrix with intercept column, shape (500, 3)

# Normal equations: (A^T A) w = A^T y  -> solve, don't invert
w = np.linalg.solve(A.T @ A, A.T @ y)

# More robust (SVD-based):
w2, *_ = np.linalg.lstsq(A, y, rcond=None)
print(w.round(3), np.allclose(w, w2))        # about [ 3.  2. -1.5]  True

pred = A @ w
ss_res = ((y - pred) ** 2).sum()
ss_tot = ((y - y.mean()) ** 2).sum()
print("R^2 =", round(1 - ss_res / ss_tot, 4))
print("RMSE =", round(float(np.sqrt(np.mean((y - pred) ** 2))), 3))

NumPy case 5: moving averages, z-scores and outliers

pandas case 1: e-commerce sales — clean, analyse, report

Problem. Given messy order data, clean it, compute revenue KPIs, and find the top customers, best months and best categories.

import numpy as np, pandas as pd

rng = np.random.default_rng(0)
n = 2000
orders = pd.DataFrame({
    "order_id": np.arange(1, n + 1),
    "customer": rng.choice([f"C{i:03d}" for i in range(1, 121)], n),
    "date": pd.to_datetime("2024-01-01") + pd.to_timedelta(rng.integers(0, 365, n), unit="D"),
    "category": rng.choice(["Electronics", "Home", "Toys", "Books", " books ", "TOYS"], n),
    "qty": rng.integers(1, 6, n).astype(float),
    "unit_price": rng.choice([9.99, 19.5, 49.0, 199.0, np.nan], n, p=[.3, .3, .2, .15, .05]),
})
orders.loc[rng.choice(n, 30, replace=False), "qty"] = np.nan

# ---- 1. Inspect
orders.info(); print(orders.isna().sum())

# ---- 2. Clean
orders["category"] = orders["category"].str.strip().str.title()          # ' books ' -> 'Books'
orders["qty"] = orders["qty"].fillna(1).astype(int)
orders["unit_price"] = orders["unit_price"].fillna(
    orders.groupby("category")["unit_price"].transform("median"))       # group-wise imputation
orders = orders.drop_duplicates("order_id")

# ---- 3. Feature engineering
orders["revenue"] = orders["qty"] * orders["unit_price"]
orders["month"] = orders["date"].dt.to_period("M")
orders["weekday"] = orders["date"].dt.day_name()

# ---- 4. KPIs
print("Total revenue:", round(orders.revenue.sum(), 2))
print("Average order value:", round(orders.revenue.mean(), 2))

by_cat = (orders.groupby("category")
                .agg(orders=("order_id", "size"), revenue=("revenue", "sum"), avg_qty=("qty", "mean"))
                .sort_values("revenue", ascending=False))
print(by_cat)

monthly = orders.groupby("month")["revenue"].sum()
print(monthly.pct_change().round(3).tail(3))            # month-over-month growth

top10 = orders.groupby("customer")["revenue"].sum().nlargest(10)
print(top10.head(3))

pivot = orders.pivot_table(index="month", columns="category", values="revenue", aggfunc="sum", fill_value=0)
print(pivot.iloc[:3])
share = by_cat["revenue"] / by_cat["revenue"].sum()      # revenue share per category
print(share.round(3))

pandas case 2: Titanic-style survival analysis with missing data

Problem. Explore which passenger factors relate to survival while handling missing ages and cabins.

rng = np.random.default_rng(3)
n = 891
df = pd.DataFrame({
    "pclass": rng.choice([1, 2, 3], n, p=[.24, .21, .55]),
    "sex": rng.choice(["male", "female"], n, p=[.65, .35]),
    "age": rng.normal(30, 14, n).clip(1, 80),
    "fare": rng.lognormal(3, 1, n),
    "cabin": rng.choice([None, "C85", "E46", "B28"], n, p=[.77, .08, .08, .07]),
})
p = 0.25 + 0.25 * (df.sex == "female") + 0.15 * (df.pclass == 1) - 0.08 * (df.pclass == 3)
df["survived"] = (rng.random(n) < p).astype(int)
df.loc[rng.choice(n, 177, replace=False), "age"] = np.nan

# Missing-data audit
print((df.isna().mean() * 100).round(1))

# Impute age by group medians (sex x class); flag that it was imputed
df["age_missing"] = df["age"].isna()
df["age"] = df["age"].fillna(df.groupby(["sex", "pclass"])["age"].transform("median"))

# Cabin: missingness is itself informative
df["has_cabin"] = df["cabin"].notna()

# Overall and segmented survival rates (mean of a 0/1 column = rate)
print("overall:", round(df.survived.mean(), 3))
print(df.groupby("sex")["survived"].mean().round(3))
print(df.pivot_table(index="pclass", columns="sex", values="survived", aggfunc="mean").round(2))

# Age bands
df["age_band"] = pd.cut(df.age, [0, 12, 18, 40, 60, 100], labels=["child", "teen", "adult", "mid", "senior"])
print(df.groupby("age_band", observed=True)["survived"].agg(["mean", "size"]).round(3))

# Fare quartiles
df["fare_q"] = pd.qcut(df.fare, 4, labels=False)
print(pd.crosstab(df.fare_q, df.survived, normalize="index").round(2))

# Correlation of numeric drivers
print(df[["survived", "age", "fare", "pclass"]].corr().round(2)["survived"])

pandas case 3: stock prices — returns, rolling stats, resampling, drawdown

Problem. From daily closes compute returns, volatility, moving averages, a crossover signal, monthly resampling and maximum drawdown.

rng = np.random.default_rng(5)
idx = pd.bdate_range("2023-01-02", periods=500)
close = pd.Series(100 * np.exp(np.cumsum(rng.normal(0.0004, 0.012, len(idx)))), index=idx, name="close")

ret = close.pct_change()                              # simple daily return
log_ret = np.log(close).diff()                        # log return (additive over time)

vol_20 = ret.rolling(20).std() * np.sqrt(252)         # annualised 20-day volatility
sma_20, sma_50 = close.rolling(20).mean(), close.rolling(50).mean()
signal = (sma_20 > sma_50).astype(int)                # 1 when fast MA above slow MA
trade = signal.diff().abs().fillna(0)                 # 1 on crossover days
print("crossovers:", int(trade.sum()))

# Strategy return: hold when signal==1, using YESTERDAY's signal (avoid look-ahead bias!)
strat = ret * signal.shift(1)
print("buy&hold:", round((1 + ret.fillna(0)).prod() - 1, 3),
      "strategy:", round((1 + strat.fillna(0)).prod() - 1, 3))

# Resample to month-end
monthly = close.resample("ME").last()
monthly_ret = monthly.pct_change()
print(monthly_ret.tail(3).round(4))

# Maximum drawdown
running_max = close.cummax()
drawdown = close / running_max - 1
print("max drawdown:", round(drawdown.min(), 3), "on", drawdown.idxmin().date())

# Calendar effects
by_wd = ret.groupby(ret.index.day_name()).mean().round(5)
print(by_wd)

What you learn: DatetimeIndex slicing, pct_change, rolling, shift to prevent look-ahead bias, resample, cummax for drawdown, grouping by index attributes.

pandas case 4: customers and orders — merge, RFM segments, cohort retention

Problem. Join customer and order tables, score customers by Recency / Frequency / Monetary value, and build a monthly cohort retention table.

rng = np.random.default_rng(11)
customers = pd.DataFrame({
    "customer_id": range(1, 301),
    "signup": pd.to_datetime("2024-01-01") + pd.to_timedelta(rng.integers(0, 180, 300), "D"),
    "country": rng.choice(["IN", "US", "UK", "DE"], 300),
})
orders = pd.DataFrame({
    "order_id": range(1, 3001),
    "customer_id": rng.integers(1, 340, 3000),          # some ids have no customer row!
    "date": pd.to_datetime("2024-01-15") + pd.to_timedelta(rng.integers(0, 300, 3000), "D"),
    "amount": rng.gamma(2, 40, 3000).round(2),
})

# Audit the join before trusting it
chk = orders.merge(customers, on="customer_id", how="left", indicator=True, validate="many_to_one")
print(chk["_merge"].value_counts())                     # left_only = orphan orders
df = chk[chk["_merge"] == "both"].drop(columns="_merge")

# RFM
snapshot = df["date"].max() + pd.Timedelta(days=1)
rfm = df.groupby("customer_id").agg(
    recency=("date", lambda s: (snapshot - s.max()).days),
    frequency=("order_id", "nunique"),
    monetary=("amount", "sum"),
)
rfm["R"] = pd.qcut(rfm.recency, 4, labels=[4, 3, 2, 1]).astype(int)          # recent = high score
rfm["F"] = pd.qcut(rfm.frequency.rank(method="first"), 4, labels=[1, 2, 3, 4]).astype(int)
rfm["M"] = pd.qcut(rfm.monetary, 4, labels=[1, 2, 3, 4]).astype(int)
rfm["segment"] = np.select(
    [(rfm.R >= 3) & (rfm.F >= 3), (rfm.R <= 2) & (rfm.F >= 3), rfm.R >= 3],
    ["Champions", "At risk", "New / recent"], default="Others")
print(rfm["segment"].value_counts())
print(rfm.groupby("segment")[["recency", "frequency", "monetary"]].mean().round(1))

# Cohort retention: signup month vs months since signup
df["order_month"] = df["date"].dt.to_period("M")
df["cohort"] = df["signup"].dt.to_period("M")
df["age_m"] = (df["order_month"] - df["cohort"]).apply(lambda x: x.n)
df = df[df.age_m >= 0]
cohort = df.pivot_table(index="cohort", columns="age_m", values="customer_id", aggfunc="nunique")
cohort_size = df.groupby("cohort")["customer_id"].nunique()        # customers per cohort
retention = cohort.div(cohort_size, axis=0).round(2)               # share of the cohort active in month k
print(retention.iloc[:3, :4])

What you learn: merge auditing with indicator and validate, groupby.agg with lambdas, qcut scoring, np.select for rule-based segmentation, Period arithmetic, pivot_table for cohorts, div(..., axis=0).

pandas case 6: A/B test analysis

Problem. Compare conversion between control and treatment; compute lift, a confidence interval and a z-test with only pandas and NumPy.

rng = np.random.default_rng(21)
n = 20000
ab = pd.DataFrame({
    "user": np.arange(n),
    "variant": rng.choice(["control", "treatment"], n),
    "device": rng.choice(["mobile", "desktop"], n, p=[.7, .3]),
})
base = np.where(ab.variant == "treatment", 0.115, 0.100)
ab["converted"] = (rng.random(n) < base).astype(int)

summary = ab.groupby("variant")["converted"].agg(users="size", conversions="sum", rate="mean")
print(summary)

c, t = summary.loc["control"], summary.loc["treatment"]
lift = t.rate / c.rate - 1
p_pool = (c.conversions + t.conversions) / (c.users + t.users)
se = np.sqrt(p_pool * (1 - p_pool) * (1 / c.users + 1 / t.users))
z = (t.rate - c.rate) / se
from math import erf, sqrt
p_value = 2 * (1 - 0.5 * (1 + erf(abs(z) / sqrt(2))))
print(f"lift={lift:.1%}  z={z:.2f}  p={p_value:.4f}")

# Segment view — heterogeneity by device
seg = ab.pivot_table(index="device", columns="variant", values="converted", aggfunc="mean")
seg["lift"] = seg["treatment"] / seg["control"] - 1
print(seg.round(3))

What you learn: groupby.agg with different summaries of the same column, label-based access to a summary table, computing statistics with vector maths, pivot_table for segment comparisons.

NumPy vs pandas: when to use which
NumPy pandas
Data homogeneous n-dimensional numeric arrays heterogeneous, labelled tables and time series
Index integer positions labels (any hashable) with automatic alignment
Missing values NaN only (floats) NaN, NaT, pd.NA, nullable dtypes
Best at maths, linear algebra, images, simulation, ML kernels cleaning, joins, groupby, time series, I/O
Speed fastest for raw numerics slower per operation (labels, dtypes) but far more expressive
std default ddof=0 ddof=1
NaN in sum/mean propagates skipped by default

Workflow pattern: load with pandas → clean and reshape with pandas → hand df.to_numpy() to NumPy / scikit-learn for heavy numerical work → put results back into a DataFrame.

Memory hooks
  • axis = the dimension that disappears: axis=0 collapses rows (column results).
  • loc = label (end included). iloc = integer position (end excluded).
  • View = same memory (basic slice). Copy = new memory (fancy / boolean index).
  • Broadcasting = align from the right; sizes must match or be 1.
  • groupby = split → apply → combine; agg shrinks, transform keeps shape.
  • merge default is inner; check keys before you trust it.
  • Vectorise everything; loops are the last resort.
